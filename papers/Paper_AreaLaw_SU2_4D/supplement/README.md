# Supplementary material: "An area law for four-dimensional SU(2) lattice gauge theory up to β ≈ 0.813" (version 1.0, 1 November 2026)

This folder accompanies the note `../note/area_law_su2_4d_v1_0.pdf`. Section numbers below refer to the note. SHA-256
fingerprints of every file are in `../SHA256SUMS`; those of the files used by the proof are also printed in Section 9 of the note.
Comments and messages in the programs are in French.

## `certification/`: the programs of the proof (Section 6)

| file | role |
|---|---|
| `c1_poids_exacts.py` | exact rational enclosures of the weights Ã_n(J), n ≤ 12, and the non-increasing majorants p_n/2^40 (Section 6.1); writes the weights file |
| `c2_poids_flint.py` | Arb (python-flint) cross-check of the enclosures, with the guard against silent truncation of power series at `ctx.cap` (Section 6.4); not part of the certification |

## The memory-11 certificate

The certificate of Theorem 2.1 is the file `certificat_h_m11_J40674_100000.bin`: 125 136 920 bytes, little-endian 64-bit words
n, n codes, n values of H, A, B (format in Section 9 of the note), SHA-256
`b50d3769b0ea17d1da13f4e870a7786407192a9885ecceb390ef18cde50cf142` (the fingerprint printed in Section 9). A raw file of this size
cannot be stored on GitHub (limit 100 MB), so this folder carries it compressed, as `data/certificat_h_m11_J40674_100000.bin.xz`
(8 780 360 bytes, `xz -9e`, XZ Utils 5.8.3). The Zenodo record that archives this release also carries the raw file.

Unpack and check the fingerprint (from this folder):

```
cd data
xz -dk certificat_h_m11_J40674_100000.bin.xz        # -k keeps the .xz file
echo "b50d3769b0ea17d1da13f4e870a7786407192a9885ecceb390ef18cde50cf142  certificat_h_m11_J40674_100000.bin" | sha256sum -c -
cd ..
```

Either of the two following ways gives the same file, byte for byte.

1. Unpack it as above (under one second).
2. Regenerate it from the programs (about 20 s on 8 cores, peak resident memory 475 MB); the program prints
   `rho_cert=2639854083/1073741824`:

```
python3 certification/c1_poids_exacts.py 40674 100000 12 10 w.txt c1.json
cmp w.txt data/poids_m11_J40674_100000.txt && echo "weights file identical"
gcc -O3 -fopenmp -o certification/tm_cert certification/tm_cert.c -lm
certification/tm_cert 11 w.txt H.bin
sha256sum H.bin          # b50d3769b0ea17d1da13f4e870a7786407192a9885ecceb390ef18cde50cf142
```

These commands were run again on a copy of this folder on 1 November 2026: the weights file, `c1.json` and the certificate
regenerated by `tm_cert 11` (twice) are byte-identical to the ones described here, and `verif_cert` accepts the certificate (see
the section "Commands").
The certificate for m = 13 (not included, SHA-256 above) can be regenerated in the same way with `tm_cert 13` and the weights file
`data/poids_m13_J40749_100000.txt` (about 20 minutes; checking it needs about 11 GB of memory); that command was not run again for
this folder.

## `lean/`: the Lean 4 formalisation (Section 9)

A Lean 4 project (Lean 4.34.0, Mathlib v4.34.0; about 1 800 lines, a large part of them data) that states Theorem 2.1 for the Wilson measure on the
torus, with the normalised Haar measure on SU(2) = S³, and proves part of its proof. It holds sources only (no `.lake` directory, no
build artefact); its comments are in French. The statement is written for the rectangle with a corner at the origin in the plane of
the first and fourth axes (the other loops follow by symmetries of the torus, not formalised), and the expectation is the quotient of
the two Haar integrals (integrability not formalised).

| status | content |
|---|---|
| **Proved in the Lean kernel**: axioms `propext`, `Classical.choice`, `Quot.sound` only; no `sorry`, no `native_decide`; the main theorems and their closure (43 458 declarations) are also accepted by the independent kernel nanoda 0.4.19 | the combinatorial part (`Perron.lean`, `Marches.lean`, `Enonce.lean`: `marches_le_certificat`, `borne_marches_tout_n`, `Nwin_le_Ntor`, `longueur_ge`, `prodVisites_cons`, `GtildeA_le`); the correctness of the certificate checker for every function `Hof` (`Calcul.lean`, `Certificat.lean`: `certificat_of_verifiePar`); the certificates of memory 3, 4 and 5 by `decide +kernel` (`CertPetits.lean`; m = 3, 4: J = 0.39859, β ≤ 0.79718, above 12/17; m = 5: J = 0.40219, β ≤ 0.80438); the final arithmetic (`Arith.lean`: `theta11_lt_one`, `K11_bornes`, `C11_bornes`); `Poids.lean` (Ã_n > 0, Ã_1 ≤ 1/2); the junction theorem `theoreme1_de_verifiePar` (`Enonce.lean`): for every `Hof` for which the checker returns `true` on the memory-11 data, and under `HypothesesBS`, the bound of Theorem 2.1 holds for β ≤ 0.81348 |
| **Established by compiled execution** (trust: the Lean and C compilers and the runtime, not the kernel) | the memory-11 certificate, on all 6¹¹ = 362 797 056 raw states, by `verifcert` (`VerifCert.lean`), which evaluates the function whose correctness is proved above; `Hof` is read from the file of `tm_cert` (a faulty reading could give `true` only if the values read were themselves a valid certificate) |
| **Assumed**: the three fields of the structure `HypothesesBS` (`Enonce.lean`) | `reduction`: \|⟨W_γ⟩\| ≤ 2^T G̃^T (equation (4.3) of the note: slab decomposition, walk representation, trace formula, Lemma 4.1, Propositions 4.2 and 4.3, Corollary 4.5; Sections 3 and 4); `monotonie`: Lemma 5.1; `poids_certifies`: r̃(N; J*) ≤ p_min(N,13)/2^40 (Proposition 5.4(1); the rational enclosures of `certification/c1_poids_exacts.py` are not redone in Lean) |

The Lean theorem for β ≤ 0.80438 (`theoreme_m5_conditionnel`, memory 5, the three hypotheses taken at J* = 40219/10⁵ with the
corresponding weights) rests on these three hypotheses alone; the theorem for β ≤ 0.81348 rests on them and on the compiled
execution. Not formalised: the string-tension corollary (Corollary 2.2), the memory-13 statement (Remark 2.3) beyond the arithmetic θ*₁₃ < 1,
the symmetries of the torus, the integrability of the integrands.

The comments of the Lean files refer to the numbering of the author's internal proof file, not to that of the note. Correspondence:
Lemma 4.2 (Peter–Weyl) = Lemma 4.1 of the note; Proposition 4.3 = Proposition 4.2; Proposition 4.4 (Hölder–Schatten) = Proposition 4.3;
Lemma 5.1 = Lemma 4.4; Corollary 5.2 = Corollary 4.5; Lemma 5.3 (revisits) = Lemma 4.6; Lemma 6.1 = Lemma 5.1; Lemmas 7.1 and 7.2 =
Lemmas 5.2 and 5.3; Section 7 = Sections 5.2, 5.3 and 6; Section 8 = Section 5.4; equation (5.1) = equation (4.3).

Rebuild and check (from `lean/`; about 17 GB of memory at the peak, because of the kernel checks of `CertPetits.lean`):

```
cd lean
lake exe cache get                       # downloads the compiled Mathlib (otherwise lake compiles it: hours)
lake build                               # checks every theorem of the library in the Lean kernel
lake env lean PrintAxioms.lean           # the axioms of the main theorems: only propext, Classical.choice, Quot.sound
grep -rn "sorry\|native_decide" LoiAire LoiAire.lean PrintAxioms.lean VerifCert.lean VerifBanc.lean   # prints nothing
```

Compiled check of the memory-11 certificate (it needs the unpacked certificate, see above). The author's run, with the 36 parallel tasks of
`verifiePar` on a heavily loaded machine, took 1 h 42 min of wall-clock time and 26 874 s (about 7.5 hours) of CPU time, with 145 MB of memory
(`lean/logs/verifcert_m11.log`):

```
lake build verifcert
.lake/build/bin/verifcert ../data/certificat_h_m11_J40674_100000.bin ../data/poids_m11_J40674_100000.txt
```

The last lines must read `verifiePar 2 11 p_m11 (2^40) A_m11 B_m11 Hmin_m11 Hmax_m11 Hof = true` and
`CertificatPerron 11 p_m11 (2^40) A_m11 B_m11 Hmin_m11 Hmax_m11 : ETABLI (par exécution compilée)`. The second-kernel check used the
export of `lean4export` (v4.34.0) of the constants listed in `second_kernel_constantes.txt` and nanoda (`nanoda_lib` 0.4.19), with
only the three axioms permitted; the script depends on the author's tool directories and is not included, but its output is in
`logs/nanoda_pipeline.log`.
